# 上下文健康度规则 — 称呼心跳与记忆模糊检测

## 核心原理
本规则利用「称呼」和「总结」作为 AI 记忆的**心跳信号**。
当心跳信号消失时，说明上下文窗口即将溢出，AI 记忆开始模糊，
必须立即执行上下文压缩或重开对话。

---

## 一、称呼规则（心跳信号A）

### 默认称呼
- 用户的默认称呼为：**先生**
- 每次回复的开头必须包含称呼，例如：「先生，……」
- 用户可随时更改称呼（如「叫我老板」「叫我张总」），更改后永久生效

### 称呼位置
- 每次回复的**第一句话**必须以称呼开头
- 格式：「{称呼}，{正文内容}」
- 示例：「先生，您要求的攻击卡牌功能已完成实现。」

### 称呼丢失 = 记忆模糊警报
如果 AI 的回复中**不再包含称呼**，说明：
1. 上下文窗口已接近上限
2. AI 开始遗忘早期规则
3. 必须立即执行上下文压缩（见第四节）

---

## 二、结尾话语规则（心跳信号B）

### 结尾要求
每次回复的**末尾**必须附上一句简短的结语，内容可选：
- 鼓励类：「先生，期待您的下一步指示。」
- 确认类：「先生，以上内容请您过目，有疑问随时提出。」
- 总结类：「先生，本轮任务已完成，请确认是否继续。」
- 提醒类：「先生，请注意 PDD 已同步更新。」

### 结语丢失 = 记忆模糊警报
如果 AI 的回复中**不再有结尾话语**，说明：
1. 上下文窗口已接近上限
2. AI 开始遗忘输出格式规则
3. 必须立即执行上下文压缩（见第四节）

---

## 三、对话总结规则（心跳信号C）

### 每轮总结要求
每次完成一个任务后，在回复末尾附上**本轮对话总结**：

```
---
## 本轮总结
- 任务：{一句话描述本次任务}
- 产出：{列出产出的文件/代码/文档}
- 状态：{完成/进行中/待确认}
- 下一步：{建议的后续动作}
```

### 总结丢失 = 记忆模糊警报
如果 AI **不再输出本轮总结**，说明：
1. 上下文窗口已严重溢出
2. AI 已遗忘结构化输出规则
3. 必须立即重开对话（见第四节）

---

## 四、记忆模糊检测与应对（★核心机制）

### 三级警报系统

| 警报级别 | 触发条件 | 含义 | 应对措施 |
|----------|----------|------|----------|
| 🟢 绿灯 | 称呼+结语+总结 三者俱全 | 上下文健康 | 正常继续 |
| 🟡 黄灯 | 丢失任意1个信号 | 上下文接近上限 | 执行上下文压缩 |
| 🔴 红灯 | 丢失任意2个或全部信号 | 上下文严重溢出 | 立即重开对话 |

### 用户自检方法
用户可通过以下方式快速检测 AI 记忆状态：
1. **称呼检测**：AI 回复是否以「先生」（或设定的称呼）开头？
2. **结语检测**：AI 回复末尾是否有结尾话语？
3. **总结检测**：AI 回复末尾是否有「本轮总结」？

> 如果任意一项消失，用户应主动提醒 AI：「你的称呼/结语/总结丢了，上下文是否快满了？」

### AI 自检方法
AI 在每次回复前，必须自问三个问题：
1. 我这轮回复有没有以称呼开头？
2. 我这轮回复有没有结尾话语？
3. 我这轮回复有没有本轮总结？

如果发现自己**上一轮回复中丢失了任何信号**，必须在本轮回复开头主动报告：

```
先生，我注意到上一轮回复中丢失了{称呼/结语/总结}信号，
这表明上下文窗口可能接近上限。建议执行以下操作：
1. 执行上下文压缩（见下方）
2. 或重开对话，将关键信息迁移到新会话

先生，是否需要我执行上下文压缩？
```

## 五、上下文压缩流程

当检测到黄灯或红灯警报时，执行以下压缩流程：

### 步骤1：标记当前状态
```
先生，正在执行上下文压缩。当前会话关键信息如下：
```

### 步骤2：提取关键信息
提取以下必须保留的信息：
1. **当前任务进度**：正在做什么，做到哪一步
2. **已创建的文件清单**：列出本轮会话创建/修改的所有文件
3. **待确认事项**：哪些决策需要用户确认
4. **关键规则提醒**：防幻觉铁律、PDD维护、元素清单约束
5. **记忆文档更新**：将关键经验写入 docs/memory.md

### 步骤3：输出压缩摘要
```
## 上下文压缩摘要（可复制到新会话）
- 项目：卡牌冒险者
- 当前进度：{一句话}
- 已创建文件：{文件列表}
- 待确认：{确认事项}
- 必读规则：pdd自动维护规则.md / 防幻觉规则.md / 五步验收sop.md / 文档关联规则.md / 编程行为准则.md / 上下文健康度规则.md
- GDD约束：元素清单+禁止清单，不得自行创造元素
- 称呼设置：先生
```

### 步骤4：建议用户操作
```
先生，请选择：
A. 继续当前会话（已压缩，但可能再次溢出）
B. 重开对话，将上方压缩摘要粘贴到新会话的第一条消息中
```

## 六、称呼自定义

用户可随时修改称呼：
- 「叫我老板」→ 后续所有回复以「老板」开头
- 「叫我张总」→ 后续所有回复以「张总」开头
- 「叫我小明」→ 后续所有回复以「小明」开头

称呼修改后，AI 必须在下一轮回复中确认：
```
先生，已将称呼更新为「老板」。从现在起，每次回复将以「老板」开头。
老板，以上变更已生效，期待您的下一步指示。
```

## 七、完整回复格式示例

```
先生，您要求的"攻击"卡牌（C001）出牌功能已完成实现。

【正文内容】
- 创建了 scripts/card.js，实现了 playCard() 函数
- 伤害值 10 来自 GDD 2.2 卡牌列表 C001
- 已通过 obsidian-write 更新 PDD-COMBAT-001.md

## 自检报告
- 使用的元素：攻击(C001) ✅、战士(P001) ✅、史莱姆(E001) ✅
- 数值来源：damage:10 → GDD 2.2 C001 ✅
- 新增函数：playCard(cardId) → 执行出牌逻辑
- PDD更新：✅ 已同步

---
## 本轮总结
- 任务：实现攻击卡牌出牌功能
- 产出：scripts/card.js、PDD-COMBAT-001.md（更新）
- 状态：完成
- 下一步：建议实现"防御"卡牌（C002）

先生，以上内容请您过目，有疑问随时提出。
```

---

## 八、与其他规则的优先级

本规则（context-health）的优先级：
- 低于防幻觉铁律（防幻觉规则.md）：防幻觉 > 称呼
- 低于PDD维护（pdd自动维护规则.md）：PDD更新 > 结尾话语
- 高于普通对话：称呼+总结 > 随意回复

即：如果同时需要防幻觉检查和称呼，先完成防幻觉检查，再补称呼和总结。
