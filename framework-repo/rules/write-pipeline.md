# 6阶段写入流程规则

## 核心原则
所有文件写入必须严格按6阶段流程执行：生成→残留覆盖预审→系统校核→人工确认→写入→事后校验。

## 6阶段详细流程

### 阶段1：生成（提案者）
- **执行者**：gdd-lead/tech-lead/doc-engineer/perf-expert/memory-keeper
- **操作**：
  1. 读取相关GDD/TDD/PDD/ID-REGISTRY
  2. 生成修改提案（含修改清单：文件:行号+修改前→修改后+依据）
  3. 提交writer-agent执行残留覆盖预审
- **产出**：修改提案文档

### 阶段2：残留覆盖预审（writer-agent）
- **执行者**：writer-agent
- **操作**：
  1. 执行5类检测（见residual-coverage-check.md规则）
  2. 全部通过 → 进入阶段3
  3. 任一不通过 → 退回提案者补充修改，回到阶段1
- **产出**：残留覆盖预审报告

### 阶段3：系统校核（verify-lead）
- **执行者**：verify-lead
- **操作**：
  1. 校验ID-REGISTRY一致性
  2. 校验元素合法性（编号注册状态）
  3. 校验编号格式规范
  4. 校验数值来源（如适用）
  5. 校验通过 → 进入阶段4
  6. 校验不通过 → 退回提案者修改，回到阶段1
- **产出**：系统校核报告

### 阶段4：人工确认（用户）
- **执行者**：用户
- **操作**：
  1. 输出修改提案+预审报告+校验报告给用户
  2. 用户决策：「执行」/「修改：{内容}」/「不改」
  3. 「执行」 → 进入阶段5
  4. 「修改」 → 回到阶段1
  5. 「不改」 → 流程终止
- **产出**：人工确认记录

### 阶段5：写入（writer-agent）
- **执行者**：writer-agent
- **操作**：
  1. 使用Edit工具精确修改（不得用Write覆盖整个文件）
  2. 每次Edit后立即Read验证（约束3：行号+内容双重验证）
  3. Read验证不符 → 改用替代方法重做
  4. 写入完成后追加变更日志（当天+格式规范+Read证据行号）
  5. 维护.changelog.md
  6. 进入阶段6
- **产出**：写入完成的文件+变更日志

### 阶段6：事后校验（verify-lead）
- **执行者**：verify-lead
- **操作**：
  1. Read验证每项修改实际写入磁盘
  2. Grep全文一致性校验
  3. 变更日志与实际修改一致性校验
  4. 复审通过 → 流程完成
  5. 复审不通过 → 退回writer-agent返工，回到阶段5
- **产出**：事后校验报告

## 例外情况
- 紧急修复（P0级）：可简化为阶段1→阶段5→阶段6，事后补阶段2/3/4
- 记忆文档同步（improvement-log/memory.md）：可简化为阶段1→阶段5→阶段6
- 规则文件创建：可简化为阶段1→阶段5→阶段6
