# PDD 自动维护规则

## 触发条件
每次你写完或修改代码后，必须同步更新对应的 PDD 文档。

更新规则
读取你刚才修改的代码文件
提取以下信息并更新 PDD：
新增/修改的模块 → 更新区块 1「模块清单」
新增/修改的全局变量 → 更新区块 2「全局变量」
新增/修改的函数 → 更新区块 3「函数清单」（只记签名，不记函数体）
状态变化 → 更新区块 4「状态机」
事件/信号变化 → 更新区块 5「事件清单」
模块调用关系变化 → 更新区块 6「模块依赖」
在 PDD 末尾追加变更日志：
变更日志
[日期] [变更类型] 函数/变量名 → 变更描述
输出 PDD 变更摘要（3-5 行），告诉用户改了什么
PDD 格式铁律
函数清单格式：函数名(参数1, 参数2) → 一句话描述
绝对禁止在 PDD 中出现：function、{、}、return、var、let、const
如果不确定某条信息该不该写入 PDD，问自己："这是'有什么'还是'怎么做的'？"
"有什么" → 写入 PDD
"怎么做的" → 不写入 PDD
PDD 更新强制触发条件
以下任一情况发生时，你 MUST 先更新 PDD 再回复用户：

你新建了任何 .js / .gd 文件
你在任何现有文件中新增了函数
你在任何现有文件中新增了全局变量
你修改了状态机的状态或转换条件
你新增了事件监听或信号
禁止事项
PDD 中不得包含函数体代码
PDD 中不得包含实现细节（算法步骤）
PDD 只记录"有什么"，不记录"怎么做的"
不得遗漏任何新增的函数或变量
不得覆盖 PDD 原有内容，必须增量更新
