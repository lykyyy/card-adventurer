# 编号管理规则

## 核心铁律：注册先于写入

> **任何新元素必须先ID-REGISTRY注册编号并验证通过，方可写入任何GDD文件。**

### 新增编号标准流程
1. **申请**：设计者提交编号申请（元素类型/名称/定义源文件/数量/功能描述）
2. **验证**：ID-REGISTRY验证5项（前缀合法/序号未占用/非废弃/格式合规/预留空间）
3. **分配**：验证通过后在ID-REGISTRY中注册，标记"✅已注册"
4. **写入**：编号分配完成后，方可使用该编号在GDD文件中写入内容

### 违反后果
- 使用未注册编号写入的内容，verify-lead校验时自动标记为「未注册-疑似幻觉」
- 必须退回设计者补充注册后方可放行
- 未注册编号不得出现在任何GDD/TDD/PDD/代码中

## 编号注册强制要求
1. 新增任何游戏元素前，必须先在 ID-REGISTRY.md 中注册编号
2. 未注册的编号不得出现在代码中
3. 编号一旦分配，不得重复使用
4. 废弃的编号移入「已废弃编号」表，不删除

## 编号格式约束
- 所有编号必须符合规范格式（见 ID-REGISTRY.md）
- 编号中的字母必须大写
- 序号必须三位补零（001, 002, ..., 999）
- 不得使用临时编号（如 TBD、TEMP、NEW）

## 编号引用约束
1. 代码中引用元素时，必须使用注册的编号
2. TDD/PDD 中引用元素时，必须使用注册的编号
3. 不得使用元素名称代替编号（名称可能重复，编号唯一）
4. 不得自行创造新编号格式

## 编号校验
每次写完代码后，自检报告中必须包含：
- 使用的所有元素编号
- 每个编号在 ID-REGISTRY.md 中的注册状态
- 不在注册表中的编号标记为「未注册-疑似幻觉」

> ID变更传播规则见 [[文档关联规则 id 绑定要求]] §约束2。约束2定义"修改ID-REGISTRY中任一编号定义时"的4步Grep→Edit→Read→记录流程，由verify-lead审查传播完整性。

## 编号冲突处理
1. 发现编号冲突时（同编号不同定义），立即停止工作
2. 向人工报告冲突清单
3. 等待人工裁定后执行修正
4. 修正完成后更新ID-REGISTRY.md

## 废弃编号管理
1. 废弃编号移入ID-REGISTRY.md的「已废弃编号」表
2. 废弃编号不删除，保留追溯能力
3. 废弃编号标注替代ID
4. 代码中不得使用废弃编号

## 跨文档编号一致性
1. 同一元素在所有文档中必须使用相同编号
2. GDD/TDD/PDD/代码中的编号引用必须一致
3. 发现不一致时，以ID-REGISTRY.md为权威来源
4. 定期执行编号审计（每月一次）
