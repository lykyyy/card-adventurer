# 项目协作协议

> **优先级**：本规则高于所有其他规则。任何其他规则与本规则冲突时，以本规则为准。

---

## 一、工作流铁律

```
讨论 → 批准 → 实施
  ↑                │
  └── 变更控制 ────┘
```

**任何未经讨论和批准的内容不得写入文件。**

---

## 二、讨论记录机制

### 2.1 决策编号

每次设计讨论产生的决策使用唯一编号：`DEC-YYYYMMDD-NN`

### 2.2 决策记录格式

```
## DEC-YYYYMMDD-NN 议题标题
- 议题：{一句话描述}
- 选项：{列出所有选项}
- 结论：{选中的选项 + 详细描述}
- 理由：{为什么选择这个方案}
- 批准：{待批准 / 已批准 / 已撤销}
```

### 2.3 决策记录位置

所有决策记录在对话中输出，并汇总写入 `.changelog.md`。

---

## 三、审批节点

| 节点 | 触发条件 | 审批人 | 通过后动作 |
|------|----------|--------|-----------|
| D-Design | 新系统设计方案完成讨论 | 用户 | 进入文档化 |
| D-Draft | GDD文档草案完成 | 用户 | 进入编号注册 |
| D-Register | 新ID注册完成 | 用户 | 进入文档写入 |
| D-Write | 文档写入完成+自检通过 | 用户 | 进入下一任务 |
| D-Code | 代码实现完成+自检通过 | 用户 | 进入验收 |

**未通过的节点必须修正后重新提交，不得跳过。**

---

## 四、变更控制

| 规则 | 说明 |
|------|------|
| 未经批准的修改 | 不得执行任何文件写入操作 |
| 已批准内容的修改 | 需重新走讨论→批准流程 |
| 紧急修复(P0) | 可先执行，事后24小时内补讨论记录 |
| 变更追溯 | 所有决策在 .changelog.md 中保留审批记录 |

---

## 五、AI行为准则

| 允许 | 禁止 |
|------|------|
| 阅读文件、搜索代码 | 未经批准写入文件 |
| 提出设计方案供讨论 | 直接生成GDD文档 |
| 展示多个选项对比分析 | 跳过讨论自行决策 |
| 注册ID后等待批准再写入 | 先写入GDD再补注册ID |
| 自检后请求用户审核 | 自检后自行宣布完成 |

---

## 六、进度审查

| 频率 | 审查内容 |
|------|----------|
| 每次讨论结束时 | 确认本次决策记录完整 |
| 每个系统设计完成后 | 对照审批节点逐项确认 |
| 用户随时可要求 | 回溯任意决策的讨论记录和批准状态 |
