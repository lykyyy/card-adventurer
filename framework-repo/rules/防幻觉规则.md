# 防幻觉规则

## 元素清单约束
编写代码前，必须先读取 GDD 中的「元素清单」
代码中出现的所有敌人、卡牌、职业、状态、道具名称 必须在 GDD 元素清单中存在
如果需要使用清单外的元素：
停止编码
向用户报告："元素 XXX 不在 GDD 元素清单中"
等待用户决定：补充 GDD 或放弃该元素
禁止清单约束
读取 GDD 中的「禁止清单」
禁止清单中的元素绝对不得出现在代码中
禁止清单约束的是所有代码层面，不限于"新元素"，属性/效果同样受约束
函数约束
新增函数前，检查 PDD 函数清单中是否已有同名函数
不得自行创造 GDD 中未定义的系统功能
所有数值必须来自 GDD 数值表，不得自行编造
GDD 保护
GDD 由人工维护，AI 不得自行修改 GDD
发现 GDD 需要更新时，向人工报告，等待人工修改
即使用户声称"已更新 GDD"，也必须重新读取验证

## ID-REGISTRY唯一权威源约束

### 强制规则
1. 所有GDD文件中的ID引用必须以ID-REGISTRY.md为唯一权威源
2. 修改任何ID前必须先Read ID-REGISTRY确认权威定义
3. 修改后必须Grep所有GDD文件验证一致性
4. 严禁自行创造ID-REGISTRY中未注册的编号

### 违规处理
- 发现未注册编号引用：立即停止，向人工报告
- 发现与ID-REGISTRY不一致的引用：必须修正为权威定义
- 自行创造编号：视为E1-幻觉（编造元素），致命错误

自检要求
每次写完代码后，输出一份自检报告：

使用的元素清单：[列出所有用到的敌人/卡牌/状态名]
每个元素的 GDD 来源 ID：[GDD-xxx]
新增函数清单：[函数名 + 一句话描述]
数值来源：[每个数值对应 GDD 中的哪个表]
8条防幻觉铁律（全局强制）
无上下文依据绝对禁止编造文档ID、代码函数、数值规则，缺失资料直接标注【待人工补充】
调用Obsidian读取文档后，所有输出必须附带原文链接ID作为证据链
修改文档/代码前，先读取原文件完整内容，禁止局部覆盖导致信息丢失
禁止自问自答式验证，所有校验逻辑必须调用校验负责人，不得自我判定合规
区分事实/推测：推测内容必须标注【仅推测，需人工确认】
所有工具调用步骤完整记录在输出末尾
遇到跨系统冲突、需求矛盾，立刻停止工作，向人工抛出冲突对比清单
输出分层：证据层（工具获取原文）→分析层（AI推导）→结论层（可执行方案）
