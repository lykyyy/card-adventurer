# 五步验收 SOP

每次完成功能开发后，必须按以下 5 步执行验收：

Step 1: PDD 更新检查
确认 PDD 已按 pdd自动维护规则.md 规则更新
确认所有新增函数/变量都已记录
确认 PDD 中不含函数体代码
Step 2: 元素清单比对
列出代码中使用的所有游戏元素
逐一比对 GDD 元素清单
标记不在清单中的元素为「疑似幻觉」
Step 3: TDD-PDD 一致性
比对 TDD 定义的接口 vs PDD 记录的函数
标记 TDD 中有但 PDD 中没有的函数（遗漏）
标记 PDD 中有但 TDD 中没有的函数（越权新增）
Step 4: 数值来源验证
列出代码中的所有硬编码数值
逐一标注其在 GDD 数值表中的来源
无法标注来源的数值标记为「待确认」
Step 5: 输出验收报告
格式如下：


Plain Text

1
2
3
4
5
6
## 验收报告
- PDD 更新：✅/❌
- 元素清单比对：✅ 全部合法 / ⚠️ 发现 N 个疑似幻觉
- TDD-PDD 一致性：✅ 一致 / ⚠️ N 处偏差
- 数值来源：✅ 全部可追溯 / ⚠️ N 个待确认
- 结论：通过 / 需修正
验收不通过的功能不得归档，必须修正后重新验收。
