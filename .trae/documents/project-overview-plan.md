# 项目概览 — 卡牌冒险者（Card Adventurer）

## Summary

这是一个以 DND 星界太空船为世界观背景的**回合制卡牌冒险游戏**项目，目前处于**原型开发早期阶段**（v0.2.0）。项目使用 Trae IDE 进行开发，配合 Obsidian 文档体系管理设计文档，并计划使用 Godot 引擎作为最终运行平台。

## 2. 游戏设计概要

### 2.1 世界观
DND 宇宙星界中驾驶太空船冒险，融合 DND 5E 规则与太空歌剧元素。

### 2.2 三层玩法架构（GDD-CORE-001）

| 层级 | 名称 | 核心玩法 | 核心资源 |
|------|------|----------|----------|
| L1 | 地图层 | 星域探索·区域选择·路径规划 | 行动力AP |
| L2 | 网格层 | 5×5网格·翻牌事件·资源采集 | 探索点EP |
| L3 | 战斗层 | 回合制卡牌战斗（4角色队伍） | 战斗能量CE + 职业能量 |

### 2.3 四大职业
- **战士**：怒气驱动，高CE高HP，前排坦克
- **盗贼**：连击点驱动，中排输出
- **法师**：法力值驱动，后排远程 + 法师塔局外成长
- **牧师**：法力值驱动，后排治疗

### 2.4 六大已设计系统

| GDD | 系统 | 状态 |
|-----|------|------|
| GDD-CORE-001 | 核心玩法架构（三层·资源·难度） | draft v0.5.0 |
| GDD-BATTLEFIELD-001 | 双战场（地面3×3 + 太空船5岗位） | active v0.6.0 |
| GDD-COMBAT-001 | 战斗系统（卡牌·敌人·装备） | draft v0.3.0（架构重构中） |
| GDD-CHARACTER-001 | 角色系统（种族/出身/技能/专长/传奇道途） | verified v1.0.0 |
| GDD-CRAFTING-001 | 制作与附魔（材料/配方/副职业） | draft v0.3.0 |
| GDD-TOWER-001 | 法师塔建设（5级塔/局外成长） | draft v0.5.0 |

### 2.5 已注册元素规模
- 19个编号前缀，约90+已注册元素
- 6张活跃卡牌 + 8张已废弃卡牌
- 5种敌人，3种状态效果
- 4种族，6出身，6技能，9通用专长，8传奇专长
- 31个制作系统元素（药水/卷轴/魔杖/附魔/材料/工作台）

## 3. 技术架构

### 3.1 文档体系
- **GDD → TDD → PDD** 三文档体系（设计→技术→程序）
- 6阶段写入流程（提案→残留预审→系统校核→人工确认→写入→事后校验）
- docs/ 目录同时作为 Obsidian Vault

### 3.2 数据架构
- 所有列举性数据通过 CSV 集中管理（`data/csv/`）
- 动态架构：`_schema.csv` 中央注册 + `_foreign_keys.csv` 外键关系
- 20+ CSV 数据文件 + 本地化文件

### 3.3 现有代码
- **HTML 原型**：`card-adventurer-standalone.html` — 单文件战斗系统原型（800×600，深蓝渐变背景，玻璃态UI）
- **scripts/index.html**：与 standalone 内容基本一致（另一份副本）
- **无 Godot 脚本**：尚无任何 `.gd` 文件，Godot 版本尚未开始开发

### 3.4 Agent 体系
8个 AI Agent 角色分工协作：
- **project-director**（L1）：统筹调度
- **gdd-lead / tech-lead / verify-lead / writer-agent**（L2）：设计/技术/校验/写入
- **doc-engineer / perf-expert / memory-keeper**（L3）：文档/性能/记忆

## 6. Design 模式注意事项

当在 Design 模式下进行 UI 设计时：
- 游戏已有视觉方向：深蓝渐变（`#1a1a2e → #16213e → #0f3460`）、玻璃态（毛玻璃效果）、暗色主题
- HTML 原型固定尺寸 800×600，移动端需考虑响应式
- 所有 UI 中的游戏元素（卡牌/敌人/状态名称）必须来自 GDD 元素清单和 ID-REGISTRY
- 设计涉及游戏元素时需遵守防幻觉规则
