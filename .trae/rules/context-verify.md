# 背景设定查询规则（Design Context Verification）

## 触发条件
**在进行任何游戏设计之前**（包括但不限于：新增卡牌、设计角色、定义派系关系、策划事件、设定数值），必须先执行背景设定查询。

## 两条铁律

### 铁律A：万物皆卡牌
一切游戏内容——装备、同伴、事件、地点、资源、设施、技能、敌人——统一为卡牌格式，拥有统一字段结构（card_id / card_name / card_type / rarity / faction / art_ref / effect_text / cost / flavor_text / source / tags）。

### 铁律B：设计前必查背景
开始任何具体设计前，必须通过以下途径验证背景一致性：
1. **搜索参考文档**：检索项目中的参考文档和设定资料
2. **WebSearch 实时检索**：当本地文档不足以覆盖设计所需背景时，通过 WebSearch 获取补充信息
3. **参考同类游戏**：参考类似的游戏的设计模式与数值平衡

## 背景核查清单（设计前必须逐项确认）

| 核查项 | 查询途径 | 确认方式 |
|--------|---------|----------|
| 新角色/派系是否合理 | 搜索本地GDD + WebSearch | 确认不与其他系统冲突 |
| 装备/武器是否符合设定 | 搜索本地GDD | 核对装备描述与背景一致性 |
| 事件是否符合游戏世界 | 搜索本地GDD | 查找类似的已有事件/情节 |
| 敌人类型是否合理 | 搜索本地GDD | 核对敌人谱系表 |
| 数值设定是否合理 | 参考同类游戏的比例和范围 | 对比参考游戏数值 |

## 禁止事项

1. **绝对禁止**自行创造不存在的派系、角色、装备、敌人类型
2. **绝对禁止**编造反背景设定的派系关系
3. **绝对禁止**使用与游戏设定不符的装备/道具名称
4. **绝对禁止**在未查证的情况下定义游戏内容

## 查询执行格式

每次开始设计时，输出以下查询记录：

```
## 背景查询记录
- 设计内容：{描述本次设计内容}
- 查询途径：
  1. 本地文档查询：{文件名.Section}
  2. WebSearch查询：{关键词}（如需要）
- 发现的相关背景：
  · {引用1 + 来源行号}
  · {引用2 + 来源行号}
- 确认结论：✅ 符合背景 / ⚠️ 需修正：{具体修正内容}
```

## 与其他规则的优先级

本规则的优先级与防幻觉规则（防幻觉规则.md）**平级**，高于编程行为准则（编程行为准则 — 八荣八耻.md）。

即：设计前必须先过背景核查 → 编码前必须先过元素清单核查 → 写完后必须更新PDD。
