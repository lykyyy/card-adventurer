# 会话启动规则 — 新会话强制读取记忆

## 触发条件
每次新会话开始时（AI 的第一条回复前），必须执行以下读取流程。

## 强制读取清单
按以下顺序读取，如果文件不存在则跳过（不报错）：

1. 读取 docs/memory.md → 获取：幻觉清单、经验教训、设计决策、项目状态
2. 读取 docs/improvement-log.md → 获取：待处理改进项、未解决的错误
3. 读取 docs/GDD/ID-REGISTRY.md → 获取：已注册的元素编号
4. 读取 docs/GDD/GDD-INDEX.md → 获取：GDD 系统清单、全局禁止清单
5. 读取 docs/user-communication-profile.md → 获取：用户沟通画像

## 启动确认格式
读取完成后，AI 的第一条回复必须包含：

先生，新会话已启动。已完成记忆加载：
- memory.md：{已读取/不存在} — 幻觉记录 {N} 条，经验教训 {N} 条
- improvement-log.md：{已读取/不存在} — 待处理改进 {N} 项
- ID-REGISTRY.md：{已读取/不存在} — 已注册编号 {N} 个
- GDD-INDEX.md：{已读取/不存在} — GDD 系统 {N} 个
- 沟通画像：{已加载/不存在}
⚠️ 待处理事项：{列出前3项}
请问您今天需要做什么？

## 项目状态追踪
memory.md 中新增「项目当前状态」章节，每次会话结束时更新：
- 最后更新：{日期}
- 当前阶段：{原型开发/正式开发/测试/发布}
- 已完成系统：{系统列表}
- 进行中任务：{当前任务描述}
- 下一步计划：{计划任务}
- 已知阻塞问题：{阻塞清单}

## 优先级
- 本规则在新会话启动阶段优先级最高，新会话第一条回复前必须执行
- 会话启动后，优先级回归正常（低于防幻觉规则和项目协作协议）
- 读取失败不阻断会话，但必须在启动确认中报告
- 与 对话蒸馏规则.md 配合：会话结束时蒸馏，会话开始时加载
