# 残留覆盖完整性预审规则

## 触发条件
所有生成提案时（gdd-lead/tech-lead/doc-engineer/perf-expert/memory-keeper提出提案后、verify-lead校验前），必须由writer-agent执行残留覆盖完整性预审。

## 5类检测规范

### 检测1：文本残留检测
- **检测目标**：提案修改后，原文件中是否残留被替换的旧文本
- **检测方法**：Grep搜索旧文本的所有出现位置（按ID/名称/术语），逐一确认是否已被新文本替换
- **不通过处理**：列出残留位置，退回提案者补充修改

### 检测2：语义残留检测
- **检测目标**：提案修改后，原文件中是否残留语义等价但文本不同的旧描述
- **检测方法**：提取旧描述的语义核心，Grep搜索语义等价表达，人工确认是否需统一
- **不通过处理**：列出语义残留项，标注语义等价关系，退回提案者统一

### 检测3：别名残留检测
- **检测目标**：提案修改后，原文件中是否残留旧编号的别名/旧名称引用
- **检测方法**：查ID-ALIAS.md，对每个旧别名Grep搜索全项目引用，确认是否已更新为新编号
- **不通过处理**：列出别名残留位置，退回提案者更新引用

### 检测4：跨系统残留检测
- **检测目标**：提案修改某系统后，依赖该系统的其他系统文件是否残留旧定义/旧引用
- **检测方法**：查ID-REFERENCE-GRAPH.md，找出依赖当前系统的所有系统文件，逐一Grep搜索旧定义/旧引用
- **不通过处理**：列出跨系统残留位置，退回提案者同步更新

### 检测5：编号一致性检测
- **检测目标**：提案修改后，全项目编号引用是否与ID-REGISTRY.md一致
- **检测方法**：提取提案涉及的所有编号，Grep全项目搜索每个编号的引用，比对ID-REGISTRY.md注册状态（✅注册/❌废弃/⚠️冲突）
- **不通过处理**：列出编号不一致位置（引用废弃编号/格式违规/未注册），退回提案者修正

## 预审报告格式

```markdown
## 残留覆盖完整性预审报告
- 提案者：{Agent}
- 提案内容：{一句话描述}
- 预审执行者：writer-agent

### 检测1：文本残留
- 状态：✅通过 / ❌发现N处残留
- 残留清单：{文件:行号 + 旧文本}

### 检测2：语义残留
- 状态：✅通过 / ❌发现N处语义残留
- 语义残留清单：{文件:行号 + 语义等价表达}

### 检测3：别名残留
- 状态：✅通过 / ❌发现N处别名残留
- 别名残留清单：{文件:行号 + 旧别名}

### 检测4：跨系统残留
- 状态：✅通过 / ❌发现N处跨系统残留
- 跨系统残留清单：{系统:文件:行号 + 旧定义}

### 检测5：编号一致性
- 状态：✅通过 / ❌发现N处不一致
- 不一致清单：{文件:行号 + 编号 + 注册状态}

### 预审结论
- ✅ 全部通过，可提交 verify-lead 系统校核
- ❌ 发现N类残留，退回 {提案者} 补充修改后重新预审
```
